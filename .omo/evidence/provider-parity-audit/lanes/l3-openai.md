## Coverage ledger

`equal` below is narrowly scoped to the named behavior, not whole-file parity.

- **equal: valid Chat tool-call/result pairing and parallel ordering.** O request.rs:273-280,309-319 copies the same valid call ID into both items and emits every assistant tool call; B request translator:171-179,343-356 emits corresponding top-level call/output items. Invalid/oversize handling is not equal (L3-04).
- **equal: function tool strict defaults.** O request.rs:391-405 and B request translator function-tool branch preserve schemas and explicitly default omitted strict to false. No generic strict-schema rewrite is needed for Codex.
- **equal: JSON-schema response_format flattening.** O request.rs:177-195 and B request translator:378-401 preserve type/name/strict/schema; text verbosity is also retained. O additionally handles json_object; no live claim is made that Codex accepts that format for every model.
- **equal: default reasoning effort medium and parallel calls enabled.** O request.rs:137-155; B Chat request translator:59-72. Explicit summary preservation is a separate defect (L3-08). Neither implementation should be changed to request summaries implicitly.
- **equal: upstream stream=true/store=false on translated Chat.** O request.rs:60-64. B executor codex_executor_request.go:415-425 enforces these flags for SIWC; B Responses translator:31-36 also enforces them. Native O is not equal (L3-01).
- **equal: core usage mapping.** O events.rs:337-372 maps input/output/total/cached/reasoning to normalized usage; render.rs:18-33 exposes Chat details. B Chat response translator:205-221 maps the same input/output/total/cached/reasoning fields. O additionally distinguishes cache-field absence from zero.
- **equal: successful Chat terminal reason selection.** O render.rs:403-424 chooses tool_calls after a call, otherwise stop, with length for normalized token-limit events; B response translator:275-288 agrees for these successful cases. Incomplete filter/legacy-limit cases are L3-03.
- **equal: native Responses event and encrypted-item passthrough for already-valid Codex wire bodies.** O cp_routes.rs:822-831 -> relay.rs:4410-4418 returns stream_response without the lossy normalized event parser; A openai-responses.ts:2348-2350 documents ordinary verbatim relay. Thus native function_call_output, reasoning encrypted_content, instructions/include and response.completed are not lost by the compatibility renderer. Unsupported envelope fields still need L3-01 normalization.
- **equal: selected-account authorization/account ID.** O relay.rs:1748-1752 takes member headers; providers/src/account.rs:107-115 supplies bearer and chatgpt-account-id. B executor request.go:513-520,570-574 supplies selected bearer/account ID. A adapter:2157-2161 overrides both from selected account. Auxiliary provider file was read solely to validate delegated header construction.
- **Reviewed: session/thread/cache identity.** O relay.rs:4714-4723 hashes a stable identity; :4750-4764 uses explicit body cache key first; :1791-1810 synthesizes session_id and session-id. A forwards session_id/session-id/thread-id at adapter:36-44 and :2151-2155; B executor request.go:545-551 forwards thread/session metadata. These are not identical policies; no demonstrated failure is inferred from identity rewriting alone.
- **Reviewed: originator/OpenAI-Beta.** O delegated Codex account header builder contains neither; A forwards caller values (adapter:36-41), B sets default originator for OAuth (executor request.go:564-574). Missing headers alone does not establish a concrete failed request, so no speculative FIX is filed. Warmup has its own different header policy and is not proof that relay requires the same values.
- **Reviewed: native compact.** O cp_routes.rs:865-874 forwards to Codex compact with original body. B executor request.go:462-475 specifically strips stream/store for SIWC compact. No runtime rejection was established for O's Codex credential/endpoint path; do not apply SIWC-only rules blindly. Non-native summary compact is concretely wrong (L3-07).
- **Reviewed: non-native Responses rendering.** O responses.rs has monotonic sequence stamping, closes items before response.completed/incomplete, and response.failed on premature EOF (:1174-1239). No assertion of complete canonical SSE-event parity: text done/content-part done and reasoning-summary event taxonomy warrant a separate focused protocol fixture comparison before classification.
- **Reviewed: error behavior.** Native successes pass upstream streams; translated parser handles response.failed/incomplete/cancelled and top-level error but keeps message only (events.rs:312-331). Chat failures emit error then DONE. No unsupported claim of full error-object fidelity or HTTP error parity is made; L3-03 is the concrete terminal misclassification found.
- **Reviewed: model listing and inbound authentication.** models_route.rs projects active registry/provider bindings and scoped visibility rather than copying A's Codex catalog. inbound.rs authenticates before relay and protects management/scoped boundaries. These structures differ; no concrete OpenAI parity failure established. A codex/catalog.ts was located, but its complete entitlement/catalog semantics and B server_codex_* endpoint family were not exhaustively audited in this lane.
- **Reviewed: tool schema support file.** O compat/tool_schema.rs is explicitly Claude/Antigravity-specific; A responses-tool-schema.ts removes Responses-only schema annotations on nonnative boundaries. No rationale to apply those sanitizers indiscriminately to native Codex schemas.
