## 1. Executive Summary

Task 4 completes cryptographic specification, detached Ed25519 signature verification, RFC 8785 JSON canonicalization, and anti-downgrade rollback defense rules for the Mahoquot runtime model registry.

Key invariants implemented and verified:
1. Pure domain invariants: Pure deterministic verification without network I/O, async runtime, axum, or gateway dependencies.
2. Detached Ed25519 signature: Payload bytes and envelope metadata are covered by detached Ed25519 signature.
3. Cryptographic order of operations: Signature verification MUST precede payload parsing, schema inspection, or interpretation.
4. Monotonic version anti-downgrade: Incoming catalog_version must strictly exceed max(active_version, lkg_version). Equal (replay) and lower versions are rejected with typed VersionDowngrade error.
5. Clock skew & expiration defense: Timestamps in the far future (> now + allowed_skew_secs) are rejected with FutureTimestamp. Expired catalogs (expires_at < now) are rejected with Expired.
6. Key rotation overlap: Trusted keyring supports simultaneous active public keys, allowing graceful rotation before publisher switches private keys. Remotely supplied or unknown key IDs are rejected with UnknownKeyId.
7. Canonical RFC 8785 representation: Non-canonical JSON formatting (minification mismatch, extra whitespace, unsorted keys) is rejected with CanonicalizationMismatch.
8. Domain validation: Zero fallback-routable bindings, empty catalogs, alias cycles, and invalid IDs are rejected before catalog adoption.
