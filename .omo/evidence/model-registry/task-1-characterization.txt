## 3. Pinned Routing & Exclusivity Invariants

### 3.1 Codex Negative-Space Exclusion
Codex is the sole open-ended fallback provider, but it is strictly bounded by negative space:
- Codex MUST NOT claim any model belonging to Antigravity (`ANTIGRAVITY_MODELS`).
- Codex MUST NOT claim any model belonging to Claude (`CLAUDE_MODELS`).
- Codex MUST NOT claim any model belonging to Zcode (`ZCODE_MODELS`).
- Codex MUST NOT claim any model belonging to Vertex (`VERTEX_MODELS` or `gemini-*` / `google/*`).
- Codex MUST NOT claim any Cursor models or prefixes (`cursor-*`, `cursor/*`).
- Codex MUST NOT claim any Kiro models or prefixes (`kiro/*`, `auto-kiro`).
- Codex DOES claim all OpenAI and unmapped models (`gpt-5.6-sol`, `gpt-5.5`, `gpt-4o`, `o3-mini`, `text-embedding-3-small`, etc.).
- In relay candidate selection (`relay.rs`), when any non-Codex pool member can serve a model, Codex accounts are filtered out entirely.

### 3.2 Duplicate-Owner Ordering & Deduplication
- Order of evaluation in `model_entries`: Codex -> Antigravity -> Claude -> Zcode -> Kiro -> Cursor -> Vertex.
- In `models_payload`, deduplication preserves FIRST OWNER ENCOUNTERED.
- Example: `claude-sonnet-4-6` is listed in both Antigravity and Claude. Because Antigravity is evaluated before Claude, `claude-sonnet-4-6` is reported with `owned_by: "google"`.

### 3.3 Unsupported-Model Inheritance & Failover
- When upstream returns an account-scoped model rejection (400 with "is not supported when using Codex", "model is not supported", "INVALID_MODEL_ID", or "MONTHLY_REQUEST_COUNT", or 402):
  - `member.mark_model_unsupported(model)` adds the model ID to `member.unsupported_models`.
  - `member.supports_model(model)` immediately returns `false` on subsequent queries.
  - Adding the same model multiple times does not create duplicate entries in `unsupported_models`.
  - On pool reload / rescan, `adopt_runtime_state(target, previous)` copies `previous.unsupported_models` to `target.unsupported_models`. Dynamic unsupported model marks survive rescans across the running process.

### 3.4 Image/Video Surface Capability Gates & Error Text
- Image surface (`/v1/images/generations`, `/v1/images/edits`):
  - Supported: `IMAGE_MODELS` = `["gpt-image-1.5", "gpt-image-2"]`.
  - Rejection: HTTP 400 `{"error":{"message":"Model {model} is not supported on /v1/images/generations or /v1/images/edits. Use gpt-image-1.5, gpt-image-2, or a configured openai-compatibility image model.","type":"invalid_request_error"}}`. (No `code` or `param`).
- Video surface (`/v1/videos/generations`, `/v1/videos/edits`, `/v1/videos/extensions`):
  - Supported: `VIDEO_MODELS` = `[]` (none).
  - Rejection: HTTP 400 `{"error":{"message":"Model {model} is not supported on /v1/videos/generations, /v1/videos/edits, or /v1/videos/extensions. No reference-backed video model is configured.","type":"invalid_request_error"}}`. (No `code` or `param`).
- Unknown provider error:
  - `{"error":{"message":"unknown provider for model {model}","type":"invalid_request_error","code":"model_not_found","param":"model"}}`.

### 3.5 Schema Wire Contracts
- `/v1/models` and `/models`:
  ```json
  {
    "object": "list",
    "data": [
      {
        "id": "<model_id>",
        "object": "model",
        "created": <unix_secs>,
        "owned_by": "<owner>"
      }
    ]
  }
  ```
- `/v1beta/models`:
  ```json
  {
    "models": [
      {
        "name": "models/<model_id>",
        "displayName": "<model_id>",
        "description": "<model_id>",
        "supportedInputModalities": ["text", "image", "audio", "video"],
        "supportedOutputModalities": ["text"], // ["text", "image"] if id contains "image"
        "supportedGenerationMethods": ["generateContent"]
      }
    ]
  }
  ```
- `/v1beta/models/{model}` (single model):
  - Exact same object as element of `/v1beta/models`, but omitting `"supportedGenerationMethods"`.

### 3.6 Settings Aliases & Exclusions Round-Trip
- Stored in `Settings`:
  - `oauth_excluded_models`: `BTreeMap<String, Vec<String>>` under YAML key `oauth-excluded-models`. Defaults to `{}`.
  - `oauth_model_alias`: `serde_json::Value` under YAML key `oauth-model-alias`. Defaults to `Value::Null`.
- Round-trips with full fidelity through `Settings::to_yaml()` and `Settings::from_yaml()`.
