## 1. Executive Summary

Task 6 implements offline-first catalog loading, Last-Known-Good (LKG) disk cache persistence, and runtime catalog management in `mahoquot-gateway` (`crates/gateway/src/registry/`).

Key architectural invariants implemented and verified:
1. Dependency & loading order:
   - Synchronous boot sequence loads embedded fallback catalog (`mahoquot_registry::embedded_registry_snapshot()`).
   - Checks configured state dir or default `~/.mahoquot/cache/models-v1.signed.json` for LKG cache.
   - If LKG exists, is valid, and has version >= embedded version, LKG is adopted with source `CatalogSource::LkgCache`.
   - Background remote update fetches signed envelope and canonical payload without blocking gateway relay hot paths.
2. Graceful error recovery & zero startup failure:
   - If LKG cache file is absent: boots cleanly with embedded catalog, recording `CatalogSource::EmbeddedFallback`.
   - If LKG cache is corrupted, has invalid signature, tampered payload bytes, or invalid JSON: logs a warning and falls back gracefully to embedded catalog without startup failure or panic.
3. Atomic LKG persistence:
   - Verified updates are persisted to disk via tempfile creation in same directory (`.{filename}.tmp.{pid}.{nonce}`).
   - Unix 0600 (`-rw-------`) mode is enforced upon file creation and verified on disk.
   - `file.sync_all()` flushes data and metadata to disk prior to atomic rename (`fs::rename`).
   - Temporary files are cleanly unlinked on write failures.
4. Active snapshot publication:
   - Snapshots are exposed lock-free through `ArcSwap<RegistrySnapshot>`, allowing zero-latency reads on relay paths.
   - Verified updates swap `Arc<RegistrySnapshot>` atomically without intermediate inconsistent states.
   - Failed remote refreshes (HTTP 500, network loss, signature tampering, downgrade) leave both active snapshot and LKG cache completely unchanged.
5. Strict anti-downgrade & network safety:
   - Remote updates require strictly monotonic catalog versions exceeding both active and LKG versions. Equal and lower versions are rejected.
   - HTTPS-only transport is enforced for remote catalogs (with loopback/localhost permitted for test harnesses). URLs with embedded credentials are explicitly rejected. Responses exceeding size caps (5MB default) are rejected.

## 4. Scenario Breakdown

### Scenario 1: Boot with no network & no LKG (Uses Embedded)
- Path: `test_boot_no_network_no_lkg_uses_embedded`
- Invariant: Cache path points to non-existent location. Boot succeeds synchronously.
- Active Version: Matches `embedded_registry_snapshot().version()`.
- Active Source: `CatalogSource::EmbeddedFallback`.
- LKG Version: `None`.

### Scenario 2: Boot with valid LKG (Uses LKG)
- Path: `test_boot_valid_lkg_uses_lkg`
- Invariant: Valid signed catalog with version 888 and custom model is present in LKG file.
- Active Version: CatalogVersion(888).
- Active Source: `CatalogSource::LkgCache`.
- Resolution: Model descriptor from LKG resolves immediately.
- LKG Version: `Some(CatalogVersion(888))`.

### Scenario 3: Boot with corrupted LKG (Falls back to embedded without crash)
- Path: `test_boot_corrupted_lkg_falls_back_to_embedded`, `test_boot_corrupted_signature_in_lkg_falls_back_to_embedded`, `test_boot_corrupted_payload_bytes_in_lkg_falls_back_to_embedded`
- Invariant: LKG contains malformed JSON, invalid signature bytes, or tampered payload bytes.
- Outcome: Manager logs warning, does not crash or panic.
- Active Version: Embedded catalog version.
- Active Source: `CatalogSource::EmbeddedFallback`.
- Status: Records warning in `last_error`, reports `lkg_version = None`.

### Scenario 4: Atomic write of new verified LKG
- Path: `test_atomic_write_of_new_verified_lkg`
- Invariant: Verified remote update is received and applied.
- Active Version: Transitioned from embedded to new version.
- Active Source: `CatalogSource::RemoteSigned`.
- Disk State: `models-v1.signed.json` exists on disk.
- Unix Permissions: File permissions verified as `0o600` (`-rw-------`).
- Reboot Test: Fresh `CatalogManager` instance rebooting from that cache path adopts version with `CatalogSource::LkgCache` without network connection.

### Scenario 5: Remote Refresh Failures Leave State Unchanged
- Path: `test_fetch_and_update_with_local_mock_server_500_leaves_active_and_lkg_unchanged`, `test_update_corrupted_signature_rejected_leaves_active_and_lkg_unchanged`, `test_update_downgrade_rejected_leaves_active_and_lkg_unchanged`
- Invariant: Remote HTTP 500 error, corrupted signature, or version downgrade attempt.
- Outcome: Error returned. Active snapshot version and source remain identical to pre-attempt state. Disk cache file is not created or modified. Status records refresh failure.
